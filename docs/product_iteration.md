# 产品迭代记录

> 本文档记录「AI 研发效能 Agent」在**产品层面**的迭代：每一版围绕
> 「发现什么问题 → 做了什么优化 → 沉淀什么能力」展开，而非纯技术更新。

## V1.0 — 基础能力验证：让答案「有依据」

**问题**

- 直接让 LLM 回答研发问题时，容易输出无依据内容。
- 用户无法判断答案可信度，也不敢直接采纳。

**优化**

- 引入 RAG 检索（Chroma + 本地中文 Embedding），答案只基于检索片段生成。
- 增加 **Citation 引用溯源**：回答用 `[1][2]` 标注真实来源（`source` / `section`）。
- 增加 **证据不足降级规则**：检索不到依据时如实告知，不强行回答。

**沉淀能力**：知识问答 + 引用溯源 + 拒答规则。

## V1.1 — Agent 流程优化：让任务「路由正确」

**问题**

- 不同任务（查知识 / 查历史 Issue / 生成测试用例）混在一起，工具调用混乱。

**优化**

- 增加 **Intent Router**：把用户输入分为
  `knowledge_query / issue_query / test_case_generation / general_chat` 四类。
- 主路径用 DeepSeek 结构化输出分类，异常时回退到确定性关键词规则（始终返回合法意图）。
- 把核心能力收敛为三个**确定性工具**：`search_knowledge / search_issue / generate_test_cases`，
  并拆解为可复用的 Skill（见 `skills/`）。

**沉淀能力**：意图路由 + 确定性工作流 + 能力拆解（Skill）。

## V1.2 — 效果评估：让质量「可量化、可反馈」

**问题**

- 缺少量化评价与持续改进机制，回答质量无法追踪。

**优化**

- 建立 **产品指标评测**：完成率 / 采纳率 / 直接采纳率 / 编辑率 / 延迟分位数（`evaluation/`）。
- 增加 **Human-in-the-Loop 反馈闭环**：采纳 / 修改后采纳 / 不采纳，写回 SQLite 供统计。
- 增加 **测试用例「依据类型」标注**：区分「文档依据 / AI 建议」，降低误用风险。

**沉淀能力**：指标统计 + 反馈闭环 + 可复现评测集。
